# R351.2 — Dynamic Backend→A2A→authenticated completion→dynamic Frontend

R350.15 demonstrated a native reviewed Engineer/Rust/EVM/OPA/Gitea/Docker PASS but scripted Task selection. R351.0–R351.1 introduced ADK Task choice, and prevented next-Task selection based on unverified A2A artifacts. R351.2 expands the real SDK A2A integration test into two variants under **the same original authenticated R349 Engineer session**.

Positive mode: a scripted ADK model selects the Backend Task and its existing signed permission pair. The original Coordinator registers the Task and a Child is issued/enrolled. The real A2A SDK Backend calls real Gateway Prepare, a native mutation-preflight class and durable Task flight. A *simulated offline Gitea CAS* then invokes the real owner-only `TrustedGatewayGiteaMutationEvidencePublisher` to publish a MAC-authenticated receipt. The separate real `AuthenticatedGiteaMutationCompletionObserver` checks the receipt, immutable commit parent, branch HEAD, and exact committed file bytes via a distinct read-only GiteaClient. Its Gitea HTTP GETs are **offline fixtures**, NOT external Gitea.

A second ADK Frontend choice is explicitly denied before the original Gateway has attested completion (zero model calls). After the owner dispatches `attestEnrolledTaskCompletion`, the real Gateway persists an independent completion journal, which unblocks the subsequent ADK Frontend dependency. The Coordinator still validates exact signed scope, dependency and epoch; it creates the second Child for the Frontend. Re-attestation is denied, and the original missing-evidence negative test is preserved.

This is a free **offline verified-gateway integration** with real MAC receipt logic and real ADK/A2A protocol. The Child VC, native VP/OPA and Gitea provider mutation in the test are simulated; it does not demonstrate live production writes or a Test Agent. The next milestone is dispatching Frontend and Test in the same session, then a paid-Gemini pilot only after explicit approval. No main mutation or merge.
