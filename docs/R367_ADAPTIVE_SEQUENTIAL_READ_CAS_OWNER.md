# R367.0 — Adaptive original-owner native read/CAS bridge

R365.3 proves the native three-role Backend → Frontend → Test Docker PASS
with SDK A2A, Rust/EVM, Gateway/OPA/Gitea and independent evidence, but
pre-registers a fixed Task DAG. R355's actual adaptive control loop
chooses Tasks dynamically but previously had only a single-effect stager.

The original Engineer Review Host now optionally binds a genuine
AuthenticatedGiteaMutationCompletionObserver pinned to its repository and
branch (not supplied by Gemini). When a model selects an exact same-file
read_file + update_file Task within its existing root permissions, the
Coordinator first admits it and the native Child is enrolled. The original
owner then reserves an immutable two-effect read/CAS journal with the
trusted Gateway, Task ID and current Gitea HEAD. The protected A2A
dispatcher accepts only that owner-issued stager; independent Gateway
evidence, not A2A text, confirms completion. A failed reservation retires
the original root. Neither Engineer grants nor Rust issuance change.

R367.0 is **integration**, not yet a new full native adaptive E2E.
The next gate is to prove actual model-selected Backend/Frontend/Test
ordering on real providers without pre-registering Tasks. Gemini authorship,
generalized source diagnostics, canonical paid launcher and GUI remain open.

No paid inference, no PR merge, and no change to main.

## R367.1 — pre-Task A2A lifecycle

The original Review Host no longer requires a pre-issued worker Child to
start protected SDK A2A channels. A create_branch permission still requires
its original root-signed branch Task to be independently completed first;
for an existing approved feature branch, the active original Engineer root
suffices. The first model-selected Task/Child is enrolled **after** SDK
startup. The original R350.3 offline fixture now asserts that A2A bootstrap
succeeds while Coordinator registeredTaskCount and native Child issuance
are both zero, then successfully enrolls exactly one Child afterward.
This is a focused lifecycle check with offline issuer/provider fixtures,
not the full native R367 adaptive 3-role proof.
