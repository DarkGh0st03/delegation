# R331 — three native ADK/A2A Tasks through signed Rust/EVM, Gitea, Docker

An isolated disposable native proof derived from R330 (must be SUCCESS
before running this next native gate). All three specialized roles now
use genuine Google ADK LlmAgent/Runner instances with scripted,
zero-cost local BaseLlm responses and real A2A SDK HTTP. The trusted
Orchestrator derives permissions, identities, signer Child DCs and
commit pins from the original Software Engineer authority-only ceiling,
registers three distinct role-specific owner→agent authenticated Unix
bindings, and stages each original Gateway request through the single
trusted owner. Backend and Frontend apply one Gitea CAS update each,
and Test invokes controlled Docker run_tests against the pinned Frontend
commit. All three have independent native Child VPs issued by the
private MCP bridge and verified by the Gateway's real Rust/EVM and OPA.
Every A2A report is treated as untrusted until the independent
mutation/Runner evidence observer attests the exact Task.

The Test ADK uses a 18-minute owner A2A deadline under the existing
20-minute Gateway challenge and 16-minute runner Execute timeout.
It does not widen run_tests permissions, replace the Runner owner
journal, or trust a model's Test PASS/commit SHA.

This is **scripted ADK transport and permission enforcement**, not
paid Gemini or autonomous code generation: the Account Suspension
functional reference remains an owner-staged disposable fixture,
`delegated_functional_edits=0`. Independent A2A HTTP peer identity,
role-specific stage-source HMAC isolation and D1 recovery are future
security/evaluation gates.

The new native workflow executes only on manual dispatch or a dedicated
R331 checkpoint; Fast CI only parses the script. The known-good R329
and R330 native scripts are not modified.
