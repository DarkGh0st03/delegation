# R151.79 — native acceptance-only FAIL-to-PASS fixture

## Concrete scenario

The fifth paid pilot failed independent researcher acceptance, but its saved
artifact does not identify the failed assertion. This checkpoint does not
claim to reproduce that unknown causal defect. It adds a separately opted-in,
zero-billing semantic regression to the immutable Account Suspension baseline.

The fixture changes only the service's lifecycle persistence: suspend/reactivate
save the new status but also replace the user's email. The candidate tests
cover status transitions; the unchanged researcher contract independently
requires preserved email. The expected first failed phase is therefore
researcher_acceptance, specifically service_persistence, after project PASS.

## Native recovery path

The injected source is chosen from the original signed Backend read/update
pairs. A nomination requires the actual Runner acceptance-only FAIL, all six
prior phases PASS, the exact current tested SHA, the known non-timeout
service_persistence result, one observed Backend writer, and both original root
grants in one signed Task. It yields an explicitly named acceptance repair
candidate, not a claim that requirement IDs establish causal source locations.
This fixture knows which original file it changed; that knowledge is not
available to the paid Gemini path.

The real bounded ADK proposer runs with a scripted no-network model, carries
the check IDs and candidate, and proposes Backend -> new Test. The same owner
intake, original Rust root, authenticated Gateway epoch admission, distinct
Child DCs, protected A2A, native VP verification and OPA remain in use.
The scripted Backend reads the real failed SHA through Gateway and corrects
only the observed semantic fault. It must observe a new committed SHA before
Test is armed. The retired acceptance witness independently checks exact-SHA
Docker PASS and native root revocation before opening the signed review-only
draft PR. No merge is authorized.

The Functional Signed DAG workflow has a separate R151.79 step with no model
API key. The fixture flag is cleared during the earlier read-only rehearsal,
so only the operational signed DAG can inject or repair the semantic fault.
The existing compiler and Backend/Frontend multi-file probes remain separate.

regressions passed. Static import checking passed across 579 files and 1757
relative imports. The tests cover ambiguous/stale failure evidence, wrong
phases, root scope gaps, conflicting writers, mismatched check IDs, one-use
model arming, confirmed source reads and committed write effects.

Docker is unavailable locally. The new CI step must complete successfully

## Remaining boundary

This is a deterministic zero-billing proof fixture, not an autonomous diagnosis
of arbitrary Gemini acceptance failures. The paid native harness still
nominates targets from compiler locations; no general acceptance source
attribution has been enabled there. A paid rerun remains premature until the
free native proof passes and a separately verified acceptance investigation
path is connected to the real model. No Gemini call was made; main is unchanged.
