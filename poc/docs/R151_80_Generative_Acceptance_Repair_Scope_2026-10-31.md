acceptance FAIL-to-PASS step and all three main free CI gates. That fixture

## Resulting behavior

The native paid-capable host now derives acceptance investigation options from
an actual classified acceptance-only Runner FAIL, its exact current SHA, the
original signed per-file read/update pairs, the live original root permission
set, and the source files actually written through the original Gateway.
The collector does not inspect a fault marker or reference implementation.
Ambiguous writers and files lacking the original root's paired grants are
excluded; no candidates, more than eight, timeouts or unclassified failures
cannot start this proposal path. These options do not establish causality.

The same real ADK repair proposer can select a subset of these candidates.
Each file remains assigned to its original Backend/Frontend writer. It may
schedule one role, multiple roles, several same-role Tasks, or several
same-role sources in one Task. Different Tasks cannot write the same file.
The independent Test must depend on every editor and receives only run_tests.
No branch, PR, test-edit, new root or unrelated permissions can be proposed.
Existing TypeScript/mixed-role behavior keeps its previous constraints.

The planner's choice is metadata-based: in this native mode it has no source
read tool before proposing a DAG. Actual source investigation happens inside
the NEW signed editor Tasks. An editor may read several granted files and
modify only the necessary ones. The native Gateway requires a confirmed read
of each written file within that same Task. The original Rust issuer, signed
epoch intake, private Gateway control, fresh child DC/VP, Core Rust and OPA
continue to independently enforce exact authority. Each editor Task still
must produce a changed feature SHA; a read-only/no-change editor is not
silently treated as a successful repair.

## Free proof mirrors the model-facing scope

The acceptance fixture now uses that SAME collector and proposer contract as
the real model path. The injected filename is no longer passed into the
native DAG executor or exposed as diagnostic_target. Its scripted proposal
receives the original candidate list and delegates multiple original Backend
source pairs in one fresh editor Task. Its scripted editor inspects actual
Gateway source reads until it finds the seeded semantic fault, corrects only
that source, and leaves unrelated candidate files unchanged. This remains a
deterministic no-network model fixture, not evidence of Gemini reasoning.

The source collector is not a delegation endpoint: candidate labels grant no
authority. Failed SHA, root state, proposed plan scope and fresh Test/PR
attestations remain independently checked. A genuine Runner FAIL lacking
candidate scope is returned as FAIL; it is not converted into an HTTP denial.
